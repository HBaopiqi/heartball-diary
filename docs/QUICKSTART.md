# 从下载到第一篇日记

[返回首页](../README.md) · [让 Agent 帮我配置](AGENT_GUIDE.md) · [连接心力球](MCP.md) · [遇到问题](TROUBLESHOOTING.md)

准备一台 Windows、Mac 或 Linux 电脑，以及能访问自己心力球记录的账号。第一次安装依赖和连接心力球需要联网；已有记录的浏览可以离线进行。

## 1. 下载并解压

点击[下载 ZIP](https://github.com/HBaopiqi/heartball-diary/archive/refs/heads/main.zip)，然后**解压整个文件夹**，不要直接在压缩包里运行程序。

你也可以在仓库页面点击 **Code → Download ZIP**，这是 [GitHub 的标准下载方式](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)。打开解压后的文件夹，应该能看到 `README.md`、`package.json`、`start.cmd` 和 `public` 等文件。

把它放在你容易找到的位置，例如个人文档中的 `heartball-diary` 文件夹。文件夹名可以带空格；不要放在需要管理员权限才能写入的位置。

## 2. 安装运行环境

打开 [Node.js 官方下载页](https://nodejs.org/en/download)，选择适合自己系统的 **LTS 版本**，本项目要求版本号不低于 22。Windows 可使用安装程序，Mac 可使用对应安装包；Linux 按该页的系统说明安装。

安装完成后重新打开终端。输入以下命令能看到版本号，就说明 Node 和 npm 可用：

```sh
node --version
npm --version
```

Windows 若提示不能运行 `npm.ps1`，使用 `npm.cmd --version`。不需要为这个项目修改系统脚本执行策略。

## 3. 启动网站

### Windows

双击解压目录里的 **`start.cmd`**。它会检查环境、安装缺少的依赖并启动网站。不要关闭这个启动窗口。

也可以在项目文件夹内打开终端，执行：

```powershell
npm.cmd run setup
npm.cmd start
```

### Mac / Linux

在终端进入解压后的项目目录，再执行：

```sh
bash start.sh
```

如果手动输入目录，路径含空格时用引号包住，例如 `cd "/你的路径/heartball-diary"`，将示例路径换成实际位置。

### 怎样知道启动成功

终端会显示“心力日记已启动”和本地网址，默认是：

```text
http://127.0.0.1:3210
```

把**终端实际显示的网址**复制到这台电脑的浏览器。首次进入会自动创建空的“我的资料库”；空白属于正常状态，你还没有同步自己的记录。

这是一项运行在本机的服务。关掉终端会停止服务；下次再次运行启动脚本即可。暂时不用时可在启动终端按 `Ctrl+C` 停止。

## 4. 接入你的心力球

打开右上角 **档案 → 连接心力球**，确认服务地址，点击 **连接 / 授权**，在出现的授权页面用自己的账号完成授权。回到本地页面后点击 **同步原始记录**。

具体地址说明、授权跳转和成功标志见[连接心力球](MCP.md)。本地网站的地址与 MCP 地址用途不同，不要互相替换。

## 生成第一份每日回顾

同步完成后，页面可能显示“原文已同步，待整理”。这是完整流程中的下一步：让助手阅读原话，写出每日回顾。

### 有本地 Agent

在 Agent 中打开这个项目文件夹，完成[对应工具的 Skill 配置](AGENT_GUIDE.md)，然后发送：

```text
更新心力球：使用本项目的 heartball-sync，读取当前资料库的完整原文，整理受影响日期的每日回顾、实际进展和后续安排，导入后核对状态。
```

如果你有多个资料库，请在指令里写上想更新的名字。助手需要继续访问正在运行的本地服务，因此先保持启动窗口开启。

### 只有能上传文件的聊天助手

1. 在网站的“档案 → 数据与整理”中点击 **下载原文整理包**。
2. 将整理包、本项目的 [heartball-sync/SKILL.md](../.agents/skills/heartball-sync/SKILL.md) 和 [dataset-schema.md](../.agents/skills/heartball-sync/references/dataset-schema.md) 提供给助手。
3. 发送下面的指令；若助手一次读不完，要让它分块读取并继续，不要只根据前几段写总结。
4. 保存助手生成的完整 JSON，回到同一个资料库，展开 **导入已整理的资料**，选择文件并导入。

```text
请按附带的 Skill 和资料格式，完整阅读原文整理包中的 sentences、asrText 及历史 rawText，以包里的 dataset 为基底生成可导入的完整 JSON；保留全部来源和版本字段，区分本人经历、他人发言、计划与完成，按北京时间整理每天的概览、事项、进展和后续安排。没有读完的来源保留待整理，完成后提供 JSON 文件。
```

这里的文件可能包含私人谈话。只有在你愿意将这些内容交给该助手时，才上传相应整理包。当前网页自身不会后台调用模型，也不会在你关机后继续整理。

## 看日记和导出日报

进入“每日回顾”选择日期，查看当天概览和事项；点击来源按钮可核对原文。右上方 **导出日报** 会下载 PDF；完整资料备份使用 **全部记录 → 导出资料**。

新手核对这三个结果即可：原始记录数量符合预期、每日回顾已经出现、同步信息里的整理状态正确。没有取回原文的时段不会被补写成虚构经历。

## 备份与升级

| 要保留的内容 | 怎么保存 |
| --- | --- |
| 可导入的日记资料和当前收藏 | 每份资料库使用“全部记录 → 导出资料”保存 JSON |
| 服务端所有资料库、原始响应、设置和授权 | 停止服务后，将整个 `data/` 文件夹备份到自己控制的位置；若配置了 `HEARTBALL_DATA_DIR`，备份那个目录 |
| 日常分享 | 选择日期导出 PDF，并检查里面的内容是否适合分享 |

完整 `data/` 备份含账号授权信息，只用于个人恢复，不用于提交 Issue 或公开分享。收藏保存在浏览器里，迁移时以导出的 JSON 一并保存。

**用 ZIP 升级：**先停止服务并备份，下载新版本到新文件夹，将自己的 `data/` 复制到新版本相同位置，再运行启动脚本。确认资料完整后再处理旧文件夹。

**用 Git 升级：**先停止服务并备份，在项目目录运行 `git pull --ff-only` 和 `npm ci`，然后重新启动。若提示有自己的代码修改，先保留这些修改再处理，勿直接覆盖。

直接打开 `public/index.html` 的离线资料库保存在浏览器中，与本地服务的 `data/` 分开；切换使用方式前先导出 JSON，再在目标资料库导入。
